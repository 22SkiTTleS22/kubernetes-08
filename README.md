1.Приложение упаковывается в общий Helm чарт. Фронтенд и бэкенд описываются отдельными Deployment, БД и кеш готовыми чартами с поддержкой репликации(копирование данных между экзеплярами, переключение при отказе одного из).
Образы, кол-во реплик, CPU и память в отдельных values-файлах окружения. 
2.Расчет для ресурсов приложений:
База данных должна быть отказоустойчивой. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии.
Кеш должен быть отказоустойчивый. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии.
Фронтенд обрабатывает внешние запросы быстро, отдавая статику. Потребляет не более 50 МБ ОЗУ на каждый экземпляр, 0.2 ядра. 5 копий.
Бекенд потребляет 600 МБ ОЗУ и по 1 ядру на копию. 10 копий.

3. Кол-во рабочих нод, которые справятся с такой нагрузкой:
Будем использовать одинаковые worker-ноды: 8 vCPU и 16 ГБ ОЗУ
Для каждой ноды заложим 1 vCPU и 2 ГБ ОЗУ для ОС, container runtime, kubelet, сетевых и других служебных компонентов. Тогда для приложений на одной ноде доступны:
  CPU = 7 vCPU
  ОЗУ = 14 ГБ
То есть количество рабочих нод, которые справятся с нагрузкой:
  CPU = 3 ноды
  ОЗУ = 3 ноды

4. Запас на отказ одной рабочей ноды
Добавим 4 запасную, тогда при отказе одной, останется для приложений ресурсов:
  CPU = 21 vCPU
  ОЗУ = 42 ГБ
  Это покрывает расчет для ресурсов приложений.
